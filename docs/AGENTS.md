# docs/ — 设计与计划

本目录存放设计说明、实施计划和周报，不是运行时契约。实现以 `agentloop/`、`backend/`、`frontend/` 代码和 `tests/` 为准。跨层总规则见仓库根 `AGENTS.md`。

## 放什么

- `superpowers/specs/`：阶段性设计（目标、范围、契约草案）
- `superpowers/plans/`：带日期的实施步骤和验收清单
- `reports/`：周报等回顾
- 根下少量专题说明（如 LLM 调用埋点）

用户命令、环境变量、启动方式若已稳定，应写进仓库根 `README.md`，而不是只留在某份计划里。

## 使用方式

- 执行任务前可阅读对应 spec/plan 了解背景，但与当前代码冲突时以代码和测试为准。
- 带日期的 plan 完成后不要回头改代码去迁就旧步骤。
- 一次性计划、临时验收清单、任务 prompt 留在本目录，不要写进任何 `AGENTS.md`。

## 禁止

- 不要把 `docs/` 当成第二个 schema：维度 key、run 文件字段、API 形状以代码为准。
- 不要提交 `.superpowers/` 工作产物、凭据或真实 `runs/` 数据。
- 不要为了「文档完整」去新增未实现的命令或工具链描述。
